# GitHub Profile README — Cyber Terminal Design

## Objective

Transform the existing GitHub profile README into a distinctive cyber-terminal
presentation that remains readable and professional. Reorganize and shorten the
current copy without introducing personal, professional, or technical information
that is not already present in the repository.

## Visual Direction

- Use a marked terminal and cybersecurity aesthetic.
- Build the palette around black, dark grey, and bright green accents.
- Present the opening identity block like terminal output.
- Use strong Markdown heading hierarchy, compact sections, monospace elements,
  separators, and coordinated badges.
- Keep decorative elements purposeful so the page remains easy to scan on desktop
  and mobile.

## Content Structure

1. Centered identity header with Edmondo De Simone's name and the existing roles.
2. Terminal-style `whoami` summary containing:
   - Master's student in Computer Science with a Cybersecurity curriculum.
   - Full Stack Developer.
   - Location in Salerno, Italy.
3. Concise About section based on the current biography.
4. Current Status section covering work, learning, and professional interests.
5. Security Interests section reorganizing the existing exploration topics.
6. Tech Stack section retaining JavaScript, TypeScript, Vue.js, Nuxt, and Tailwind
   CSS.
7. Personal Interests section retaining coding, cybersecurity, video games, and
   motorcycles.
8. Connection section retaining the personal website and LinkedIn profile.
9. Visitor counter and the existing closing motto.

## Content Rules

- Do not invent skills, experience, projects, employers, metrics, contact details,
  or biographical information.
- Preserve the README language as English.
- Remove repetition where the same idea appears in several sections.
- Keep the tone direct, technical, and confident.
- Continue using only the external image services already represented in the
  current or immediately preceding README history: Shields.io, Skill Icons, and
  the profile visitor counter.

## Implementation Constraints

- The deliverable remains a single `README.md` that renders correctly on GitHub.
- Use GitHub-compatible Markdown and conservative inline HTML.
- Avoid scripts, unsupported CSS, and layouts that depend on fixed screen widths.
- Include meaningful alternative text for linked images and badges.

## Preview and Verification

- Start a local Markdown preview server during implementation so changes can be
  inspected as they are made.
- Verify the final source structure, links, image URLs, and Markdown formatting.
- Inspect the rendered desktop view and a narrow mobile-sized view.
- Confirm that every factual statement can be traced to the original README.

## Success Criteria

- The profile immediately communicates a strong cyber-terminal identity.
- The opening section makes the name, role, study focus, and location easy to find.
- The page is substantially easier to scan than the current plain-text version.
- No unsupported or unknown facts are added.
- The GitHub-rendered README remains legible on both desktop and mobile.
